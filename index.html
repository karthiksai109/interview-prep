What the AT&T round told us

You were hit with four probe lines. Final-round interviewers at peer banks reuse this exact playbook, so each has a dedicated dossier here:

  1. "If you don't pass context to AWS Bedrock, how will it answer?" → Bedrock & context dossier
  2. "How are agents assigned — on what basis?" → Routing section of the Verizon architecture page
  3. "How did you ingest data for the LLM?" → Ingestion pipeline section
  4. "Walk me through the 6-agent architecture." → Full walkthrough with diagram logic
Why they ask this way
Final-round engineers aren't testing definitions. They're checking whether you understand the physics of the system you claim to have built: where state lives, what fails without context, how routing decisions are made, and where the cost and latency go. Every answer should name the component, the tradeoff, and a number (latency, token budget, error rate) from your project.

The answer formula that wins rounds

1 · Define in one line

Show you know the precise mechanism. One sentence, correct vocabulary (stateless API, tokenizer, HNSW index).

2 · Show it in your system

Attach it to Verizon or Epsilon immediately: "In the 6-agent platform, that showed up as…" with an actual number.

3 · Name the edge case

Finish with what breaks and how you'd detect it. That's the senior-engineer signal juniors never give.
