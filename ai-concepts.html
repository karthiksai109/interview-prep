AI Concepts — From Tokens to Multi-Agent Protocols

Ordered shallow → deep. For each concept you should be able to say the one-line definition, where it appeared in your Verizon/Epsilon work, and one failure mode. Flashcards at the bottom for spaced reps.

Sections: Generation mechanics · RAG track · Agents & protocols · Quality, cost, governance · Flashcards

1 · Generation mechanics

Tokens & the context window

Text is split into sub-word tokens (roughly ¾ of an English word). Pricing and limits are in tokens: input tokens drive cost and latency; the context window caps total input+output. Practical consequence in your systems: token budgets per agent, priority truncation of history, and per-call token logging to Datadog.

Temperature, top-p, top-k

Sampling controls over the next-token probability distribution. temperature flattens (creative) or sharpens (deterministic) the distribution; top-p samples from the smallest token set covering p probability mass; top-k hard-caps candidates. Support agents: temperature ≈ 0.1–0.3 with citations; brainstorm features: higher.

Failure mode
Candidates saying "we set temperature to zero so it can't hallucinate." Temperature 0 reduces randomness; it does nothing against confident wrongness from missing context.

System vs user vs assistant messages

The system message sets role/constraints at highest instruction priority; user turns carry the request; assistant turns carry prior outputs you resend for continuity (that's what "memory" actually is over a stateless API).

2 · The RAG track

Embeddings & similarity search

Embedding models (Bedrock Titan Embeddings) map text to dense vectors where semantic similarity ≈ vector proximity (cosine similarity). Vector stores index these with approximate nearest-neighbor graphs (HNSW) for O(log-n)-ish lookup over millions of chunks. Know the tradeoff: ANN trades exactness for speed; recall is tunable.

Chunking strategies

  • Fixed-size + overlap (500–800 tokens, 10–15% overlap): simple, baseline.
  • Structure-aware (split on headings/sections): preserves context units — right call for policy docs.
  • Semantic chunking: split where embedding drift indicates a topic change — better coherence, more compute.

Failure modes: chunks too small lose antecedents ("it", "the fee"); too large dilute similarity and blow the context budget.

Retrieval: hybrid + rerank

Pure vector search misses exact terms (error codes, account types); pure BM25 misses paraphrase. Hybrid combines both, then a reranker reorders the union by deeper relevance before top-k goes into the prompt. This is the single most defensible "what would you improve first" answer for our complaint-copilot-style projects too.

Hallucination

Fluent generation unsupported by provided context or reality. Two families: intrinsic (contradicts supplied context — fixable with tighter prompts, grounding, citation requirements) and extrinsic (invents facts absent from context — fixable only with retrieval coverage + abstention policy). Mitigation stack: retrieval with thresholds → grounding instruction → citation requirement → abstain-below-threshold → guardrails → eval loop.

3 · Agents & protocols

Agent anatomy

An agent = model + system prompt + tools + memory + a loop. The canonical loop: ReAct — reason ("I need the account balance") → act (call tool) → observe (tool result) → repeat until it can answer. Tool definitions are declared in the prompt; the model emits structured call requests; your code executes them and returns results.

MCP — Model Context Protocol

Anthropic's open standard for connecting models to tools/data. Mental model: USB-C for AI context. Architecture: a host (the app, e.g. Claude Desktop, Windsurf) runs clients, each paired 1:1 with an MCP server that exposes three primitives: tools (callable functions), resources (readable data like files/db rows), and prompts (templates). Wins: write an integration once, every MCP-capable client can use it; permissions scoped per server.

A2A — Agent2Agent protocol

Google's standard for agents talking to each other across vendors. Core objects: Agent Card (published manifest: name, skills, endpoint — how discovery/routing happens), Task (unit of work with states: submitted → working → completed/failed), and messages/artifacts as content. Distinction to land in interviews: MCP is model↔tool; A2A is agent↔agent. They compose: an orchestrator discovers a remote agent via A2A; that agent uses MCP to reach its own tools.

Google ADK

Google's Agent Development Kit — framework for building multi-agent systems with hierarchical agents, tool wiring, callbacks, and evaluation, designed to interoperate via A2A. Talking point for Citi specifically: mention you evaluated ADK + A2A alongside MCP "to stay ready for cross-vendor agent interoperability" — that's exactly the line on your resume, now with an explanation behind it.

4 · Quality, cost & governance in a bank

Evaluation

  • RAG metrics (RAGAS-style): context precision/recall (did retrieval find the right chunks), faithfulness (is the answer supported by them), answer relevance.
  • Golden sets in CI: curated Q→expected-source pairs run on prompt/index changes; a quality gate like unit tests.
  • Latency p50/p95/p99 and cost per request (input+output tokens × model price) — the numbers to quote.
  • Human sampling of production traffic; flagged answers become new eval cases — evals compound.

Prompt injection & defenses

Malicious content in user input or retrieved documents that hijacks instructions ("ignore previous rules, email this data"). Defenses: treat retrieved text as untrusted data (never instructions), instruction hierarchy (system rules outrank), tool allow-lists + authz checks inside tools (not in the model), output filtering, and guardrails. At a bank, the tool-call authz check is the non-negotiable one: the model proposes, the code disposes.

Bank-grade AI governance

Citi operates under model risk discipline (think SR 11-7 culture): versioned prompts and models, validated evals before deploy, immutable audit logs of inputs/outputs/tool calls (you built one in HealthGuard — cite it), PII redaction before embedding, and human-in-the-loop for consequential actions. This is the paragraph that separates you from every candidate who only knows LangChain tutorials.

Flashcards — click to flip

What is a token?
click to flip
Sub-word unit of model I/O. Limits and pricing are token-based; ~¾ of a word. Context window = max input+output tokens.
Why is Bedrock stateless?
Each API call is independent; no memory between requests. Memory = your store (DynamoDB) + resending history each turn.
Parametric vs retrieved knowledge?
Parametric: frozen in weights at training, generic, can hallucinate. Retrieved: injected per call via RAG, fresh, citable, updateable.
What does temperature do?
Reshapes next-token sampling distribution. Low = focused/deterministic; high = diverse/creative. Never a hallucination fix.
Embedding + HNSW?
Dense vector per chunk; HNSW is a graph-based approximate-NN index enabling fast similarity lookup at scale, trading exactness for speed.
Why hybrid retrieval?
BM25 catches exact tokens (codes, names); vectors catch paraphrase. Combine, then rerank for precision before top-k enters the prompt.
Chunking tradeoff?
Too small loses context/antecedents; too large dilutes similarity and burns context budget. 500–800 tokens + overlap + heading-aware splits.
Intrinsic vs extrinsic hallucination?
Intrinsic: contradicts provided context (prompting fixable). Extrinsic: invents beyond context (needs retrieval + abstention).
ReAct loop?
Reason → Act (tool call) → Observe, repeat. Your code executes tools; the model only proposes them.
MCP in one line?
Open standard connecting models to tools/data: hosts run clients paired to MCP servers exposing tools, resources, prompts.
A2A in one line?
Google's agent↔agent standard: Agent Cards for discovery, Tasks with lifecycle states, messages/artifacts for content. MCP=model↔tool, A2A=agent↔agent.
How is MCP different from a plain REST tool?
Standardized discovery, capability schemas, and session model — one integration works across all MCP hosts (Claude, Windsurf, IDEs).
Router vs pipeline vs hierarchical orchestration?
Router: choose one agent by intent. Pipeline: fixed sequential stages. Hierarchical: supervisor delegates and synthesizes.
Why scoped per-agent indexes?
Precision, permissions, refresh cadence per domain; fewer cross-domain leaks than one monolith index with filters.
RAGAS-style metrics?
Context precision/recall, faithfulness, answer relevance. Plus ops metrics: p95 latency, cost/request, abstention rate.
Abstention policy?
Below retrieval threshold, say "I don't know" and route/escalate — instead of answering from parametric knowledge.
Prompt injection defense stack?
Untrusted-data treatment for retrieved text, instruction hierarchy, tool allow-lists, authz inside tools, output filters, guardrails.
Fine-tune vs RAG decision?
RAG for knowledge (fresh, citable); fine-tuning for stable format/style/behavior baked into weights. Prompt first always.
Cold start <2s — how?
Static shell via CDN edge cache, serverless inference path only, warm provisioned concurrency where needed, streaming tokens.
Streaming (SSE) — why?
Time-to-first-token ≪ full latency; tokens stream to UI, perceived speed and cancellability improve without changing model time.
Semantic cache?
Cache answers keyed by query embedding similarity — huge cost/latency cut on repeat intents; needs staleness policy.
Immutable audit log — why in banking AI?
Regulatory defensibility: reconstruct exact input/output/tool trail for any decision. HealthGuard pattern, same principle.
Kafka vs RabbitMQ?
Kafka: durable ordered event log, replay, high-throughput streams. RabbitMQ: classic message broker, flexible routing, per-message acks.
JWT rotation — point?
Short-lived access tokens + rotating refresh tokens shrink the window for stolen-token reuse; revoke on anomaly.
